1 · Bounded agents

Based on the AI product I own at work

The graph the agent runs on

Each step is decided ahead of time to be run by a model, by exact logic, or by a person. Loops are allowed, and every loop has a limit.

The case

    What is real here

    At Print Reach I am the product owner and manager for an internal AI system across four products, working with engineering and colleagues. Its design uses a graph with bounded loops, context chosen for each step, human review and recorded actions and results. My hands-on agent work there primarily turns project requirements into functional mocks and prototypes.

    This page shows none of the real system. The graph, the requests and the replies are invented.

    2 · One rule set

    Schematically · open source, in beta

    Ask for a connection

    The same request goes to all three surfaces. Change it and ask again, or click two boxes in the diagram.

    The rule, written once

    The UI, the HTTP API and the MCP server all call this one function. None of them has its own copy of the rule.

    
    
    In Schematically a diagram is a model, not a drawing: boxes, boundaries, ports and wires with rules about what may connect. People edit it in the browser and agents edit it over HTTP or MCP, and every surface enforces the same rules, so a person and an agent get the same answer. This card is a small reconstruction of that idea, not the editor itself.
